nabu-fastcharge: charging driver for Xiaomi Pad 5 on Windows on ARM64

Readiness report. Check of 2026-09-16, build with Rust 1.97.0 (edition 2024), driver target - aarch64-pc-windows-msvc.

The problem

Under Windows the tablet does not charge from any power brick: from USB-A (Quick Charge) it discharges, from USB-C (Power Delivery) the capacity stays put. The reason is not the absence of "fast" charging, but that the hardware adapter detection in the PMIC runs, yet no Windows component reads its result, so the input current limit is never raised.

The driver closes this gap: it reads the detection result (APSD_RESULT_STATUS) and sets the input current limit for the recognized adapter type.

How to reproduce

git clone <repository>
cd nabu-fastcharge

cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo run -p cli -- --journal artifacts/journal-demo.jsonl demo
cargo run -p cli -- pump --profile qc35
cargo run -p cli -- verify

# hardware-free bench
cargo run -p cli -- sim --adapter hvdcp3 --listen 127.0.0.1:9700
cargo run -p cli -- detect --transport tcp --addr 127.0.0.1:9700

# driver (WDK and LLVM 17.x required)
cd crates/kmdf && cargo wdk build --target-arch arm64 --profile release
