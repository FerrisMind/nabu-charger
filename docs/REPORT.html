nabu-fastcharge: драйвер зарядки для Xiaomi Pad 5 под Windows on ARM64

Отчёт о готовности. Проверка от 16.09.2026, сборка на Rust 1.97.0 (edition 2024), цель драйвера — aarch64-pc-windows-msvc.

Задача

Под Windows планшет не заряжается ни от одного блока: от USB-A (Quick Charge) он разряжается, от USB-C (Power Delivery) ёмкость стоит на месте. Причина не в отсутствии «быстрой» зарядки, а в том, что аппаратная детекция адаптера в PMIC выполняется, но ни один компонент Windows не читает её результат, поэтому лимит входного тока не поднимается.

Драйвер закрывает этот пробел: читает результат детекции (APSD_RESULT_STATUS) и выставляет лимит входного тока под распознанный тип адаптера.

Чего пока нет

ПунктСостояниеПричина
Сборка драйвера режима ядраостановленоЦель сборки верна (ARM64), но bindgen под libclang 23 разбирает заголовки WDF неполно. Нужен LLVM 17.x — см. docs/HANDOVER.md, раздел 6
Чтение регистра через шину SPMIтипизированный отказРаскладка ответа шины не подтверждена реверсом; догадка за факт не выдаётся
Charge pump LN8000 (полные 33 Вт)следующий этапНужен отдельный драйвер I2C (адрес 0x51), протокол есть в исходниках Android

Как воспроизвести

git clone <репозиторий>
cd nabu-fastcharge

cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo run -p cli -- --journal artifacts/journal-demo.jsonl demo
cargo run -p cli -- verify

# стенд без железа
cargo run -p cli -- sim --adapter hvdcp3 --listen 127.0.0.1:9700
cargo run -p cli -- detect --transport tcp --addr 127.0.0.1:9700

# драйвер (нужны WDK и LLVM)
cd crates/kmdf && cargo wdk build
