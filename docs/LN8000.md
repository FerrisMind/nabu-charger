# LN8000 driver core

The second crate of the project ([`crates/ln8000`](../crates/ln8000)): the charge pump
logic of the LN8000 - a 2:1 converter that delivers the full charging current (up to
4.5 A into the battery with 9 V at the input).

The logic source is the driver from the reference Android sources:
`04-android-reference-sources/drivers_power_supply_ti_ln8000_charger.c` and `.h`
(GPL-2.0-or-later, Lion Semiconductor / XiaoMi, 2021). There is no driver for the
LN8000 under Windows, so the register map, the bit masks, the numeric codes and the
initialisation sequence were ported one to one from it. That makes this a derivative
work, which is why the repository is licensed GPL-2.0-or-later; see
[PROVENANCE.md](../PROVENANCE.md) for what came from where.

Not from it: the software fold-back ladder in `guard.rs` (the reference leaves thermal
handling to the chip), the mode chooser, and the derivation of the 2:1 window from the
pack voltage. Those are this project's own work, measured on the tablet.

## Why a separate crate

The LN8000 lives on a separate I²C bus (address 0x51, ACPI node `PEIC`), and not in the
SMB block of the PM8150B charger. Its operating conditions are different too: its own
registers, its own watchdog timer, its own protections. Mixing it with the SMB logic in
one crate would have complicated both.

## Register map

Addressing is single-byte.

| Address | Name | Purpose |
|---|---|---|
| `0x00` | `DEVICE_ID` | identifier, `0x42` expected |
| `0x01` | `INT1` | interrupt flags |
| `0x02` | `INT1_MSK` | interrupt mask |
| `0x03` | `SYS_STS` | operating mode and active regulation loops |
| `0x04` | `SAFETY_STS` | temperatures, reverse current |
| `0x05` | `FAULT1_STS` | watchdog timer, battery/input OV |
| `0x06` | `FAULT2_STS` | input overcurrent |
| `0x07` | `CURR1_STS` | current status |
| `0x08` | `LDO_STS` | charge termination, recharge |
| `0x09`...`0x12` | `ADC01`...`ADC10_STS` | ADC results (10 bits per channel, read as a pair) |
| `0x1B` | `IIN_CTRL` | input current limit (bits 6:0) |
| `0x1C` | `REGULATION_CTRL` | regulation loops and thermal protections |
| `0x1D` | `PWR_CTRL` | power control |
| `0x1E` | `SYS_CTRL` | mode: standby / bypass / switching |
| `0x1F` | `LDO_CTRL` | LDO control |
| `0x20` | `GLITCH_CTRL` | input overvoltage threshold (bits 3:2) |
| `0x21` | `FAULT_CTRL` | protection enables |
| `0x22` | `NTC_CTRL` | low 8 bits of the NTC threshold |
| `0x23` | `ADC_CTRL` | ADC mode (7:5), hibernation delay (4:3), high NTC bits (1:0) |
| `0x24` | `ADC_CFG` | ADC channel selection |
| `0x25` | `RECOVERY_CTRL` | auto-recovery (bits 7:4) |
| `0x26` | `TIMER_CTRL` | watchdog timer (bit 7 - enable, bits 6:5 - period) |
| `0x27` | `THRESHOLD_CTRL` | thresholds, the driver writes `0x0E` |
| `0x28` | `V_FLOAT_CTRL` | charge target voltage |
| `0x29` | `CHARGE_CTRL` | bit 7 - software initialization mark |
| `0x30` | `LION_CTRL` | unlock (`0xC6`) |
| `0x41`, `0x42` | `BC_OP_1`, `BC_OP_2` | built-in controller operations; `BC_OP_2[0]` - software reset |

## Operating modes

`SYS_CTRL` (mask `BIT(3) | BIT(0)`):

| Mode | `STANDBY_EN` (3) | `EN_1TO1` (0) | What it is |
|---|---|---|---|
| `STANDBY` | 1 | 0 | switches off |
| `BYPASS` | 0 | 1 | the input goes straight to the battery (5 V) |
| `SWITCHING` | 0 | 0 | 2:1 converter (9 V -> 4.5 V) |

The reverse decoding is by `SYS_STS`: `SHUTDOWN`/`STANDBY` -> standby,
`SWITCHING_ENABLED` (bit 2) -> switching, `BYPASS_ENABLED` (bit 3) -> bypass.

**Acceptance criterion for the prototype** (from the project roadmap):
the device answers `DEVICE_ID = 0x42` and the `SWITCHING` mode holds.

## Value encoding

| Quantity | Register | Formula | Source of the constants |
|---|---|---|---|
| Input current limit | `IIN_CTRL[6:0]` | code = current / 50 mA, minimum 500 mA | `LN8000_IIN_CFG_MIN`, `_LSB` |
| Charge voltage | `V_FLOAT_CTRL` | code = (U - 3.725 V) / 5 mV, 0...255 | `LN8000_VBAT_FLOAT_MIN`, `_LSB` |
| Input overvoltage threshold | `GLITCH_CTRL[3:2]` | 0 = 6.5 V, 1 = 11 V, 2 = 12 V, 3 = 13 V | `ln8000_set_vac_ovp` |
| NTC threshold | `NTC_CTRL` + `ADC_CTRL[1:0]` | 10 bits, low and high separately | `ln8000_set_ntc_alarm` |
| Watchdog timer | `TIMER_CTRL[6:5]` | 0 = 5 s, 1 = 10 s, 2 = 20 s, 3 = 40 s | `enum ln8000_watchdpg_cfg_desc` |
| ADC mode | `ADC_CTRL[7:5]` | 0 auto-hibernation, 1 auto-shutdown, 2 shutdown, 4 hibernation, 6 normal | `enum ln8000_adc_mode_desc` |

ADC readings (channel -> register - as in `ln8000_get_adc_data`):

| Channel | Register | Step | Offset |
|---|---|---|---|
| `IIN` | `ADC01` | 4.89 mA | - |
| `VAC` | `ADC02` | 16 mV | +5 LSB |
| `VIN` | `ADC03` | 16 mV | - |
| `VOUT` | `ADC04` | 5 mV | - |
| `VBAT` | `ADC06` | 5 mV | none (`ADC_VBAT_MIN` = 1 V - the validity threshold, not an offset) |
| `DIETEMP` | `ADC07` | 0.435 °C | -25 °C |
| `TSBAT` | `ADC08` | 2.933 mV | - |
| `TSBUS` | `ADC09` | 2.933 mV | - |

The codes are 10-bit and are read as a byte pair starting at the channel register, so the
channels overlap in bytes - this is a property of the hardware, not a modeling error.

## What the driver does

```text
open()              read of DEVICE_ID (0x42 expected)
configure()         thresholds, protections, regulation loops, ADC, initialization mark
enable_switching()  SYS_CTRL -> switching + check by SYS_STS
status()            SYS_STS / SAFETY / FAULT1 / FAULT2 / LDO
read_adc(ch)        reading of a channel
set_iin_limit()     changing the current limit on the fly
soft_reset()        LION_CTRL = 0xC6 + BC_OP_2[0] = 1 (pause >= 10 ms - on the caller side)
standby()/close()   switch to standby; Drop does the same on unload
```

## Honest limitations

* **Voltage negotiation is not our job.** The 9/11 V with the adapter are negotiated by
  the Type-C/PD part of the platform (PM8150B). Without it the LN8000 can hold the
  already negotiated voltage or work in bypass 1:1 from 5 V - this is recorded
  in the project roadmap.
* **The watchdog timer** is disabled by default, as in the Android driver. If it is
  enabled, the periodic servicing is the caller's job: the
  driver core does not sleep.
* **The real register values** are confirmed against the driver source; a check on a
  live chip has not been performed yet.
