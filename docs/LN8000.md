# Ядро драйвера LN8000

Второй крейт проекта ([`crates/ln8000`](../crates/ln8000)): логика charge pump
LN8000 — преобразователя 2:1, который даёт полный ток зарядки (до 4.5 А в
батарею при 9 В на входе).

Источник логики — драйвер из эталонных исходников Android:
`04-android-reference-sources/drivers_power_supply_ti_ln8000_charger.c` и `.h`
(GPL, Lion Semiconductor / XiaoMi, 2021). Под Windows драйвера для LN8000 нет,
поэтому формулы и последовательности перенесены один в один.

## Почему отдельный крейт

LN8000 живёт на отдельной шине I²C (адрес 0x51, узел ACPI `PEIC`), а не в SMB
зарядника PM8150B. Условия работы тоже другие: свои регистры, свой сторожевой
таймер, свои защиты. Смешивать это с логикой SMB в одном крейте значило бы
усложнить оба.

## Карта регистров

Адресация однобайтовая.

| Адрес | Имя | Назначение |
|---|---|---|
| `0x00` | `DEVICE_ID` | идентификатор, ожидается `0x42` |
| `0x01` | `INT1` | флаги прерываний |
| `0x02` | `INT1_MSK` | маска прерываний |
| `0x03` | `SYS_STS` | режим работы и активные петли регулирования |
| `0x04` | `SAFETY_STS` | температуры, обратный ток |
| `0x05` | `FAULT1_STS` | сторожевой таймер, OV батареи/входа |
| `0x06` | `FAULT2_STS` | превышение входного тока |
| `0x07` | `CURR1_STS` | состояние тока |
| `0x08` | `LDO_STS` | окончание заряда, дозаряд |
| `0x09`…`0x12` | `ADC01`…`ADC10_STS` | результаты АЦП (10 бит на канал, читаются парой) |
| `0x1B` | `IIN_CTRL` | лимит входного тока (биты 6:0) |
| `0x1C` | `REGULATION_CTRL` | петли регулирования и температурные защиты |
| `0x1D` | `PWR_CTRL` | управление питанием |
| `0x1E` | `SYS_CTRL` | режим: standby / bypass / switching |
| `0x1F` | `LDO_CTRL` | управление LDO |
| `0x20` | `GLITCH_CTRL` | порог перенапряжения входа (биты 3:2) |
| `0x21` | `FAULT_CTRL` | разрешение защит |
| `0x22` | `NTC_CTRL` | младшие 8 бит порога NTC |
| `0x23` | `ADC_CTRL` | режим АЦП (7:5), задержка гибернации (4:3), старшие биты NTC (1:0) |
| `0x24` | `ADC_CFG` | выбор каналов АЦП |
| `0x25` | `RECOVERY_CTRL` | автовосстановление (биты 7:4) |
| `0x26` | `TIMER_CTRL` | сторожевой таймер (бит 7 — включение, биты 6:5 — период) |
| `0x27` | `THRESHOLD_CTRL` | пороги, драйвер пишет `0x0E` |
| `0x28` | `V_FLOAT_CTRL` | целевое напряжение заряда |
| `0x29` | `CHARGE_CTRL` | бит 7 — отметка программной инициализации |
| `0x30` | `LION_CTRL` | разблокировка (`0xC6`) |
| `0x41`, `0x42` | `BC_OP_1`, `BC_OP_2` | операции встроенного контроллера; `BC_OP_2[0]` — программный сброс |

## Режимы работы

`SYS_CTRL` (маска `BIT(3) | BIT(0)`):

| Режим | `STANDBY_EN` (3) | `EN_1TO1` (0) | Что это |
|---|---|---|---|
| `STANDBY` | 1 | 0 | ключи выключены |
| `BYPASS` | 0 | 1 | вход идёт на батарею напрямую (5 В) |
| `SWITCHING` | 0 | 0 | преобразователь 2:1 (9 В → 4.5 В) |

Обратный разбор — по `SYS_STS`: `SHUTDOWN`/`STANDBY` → standby,
`SWITCHING_ENABLED` (бит 2) → switching, `BYPASS_ENABLED` (бит 3) → bypass.

**Критерий работоспособности прототипа** (из дорожной карты проекта):
устройство отвечает `DEVICE_ID = 0x42` и режим `SWITCHING` держится.

## Кодирование значений

| Величина | Регистр | Формула | Источник констант |
|---|---|---|---|
| Лимит входного тока | `IIN_CTRL[6:0]` | код = ток / 50 мА, минимум 500 мА | `LN8000_IIN_CFG_MIN`, `_LSB` |
| Напряжение заряда | `V_FLOAT_CTRL` | код = (U − 3.725 В) / 5 мВ, 0…255 | `LN8000_VBAT_FLOAT_MIN`, `_LSB` |
| Порог перенапряжения входа | `GLITCH_CTRL[3:2]` | 0 = 6.5 В, 1 = 11 В, 2 = 12 В, 3 = 13 В | `ln8000_set_vac_ovp` |
| Порог NTC | `NTC_CTRL` + `ADC_CTRL[1:0]` | 10 бит, младшие и старшие отдельно | `ln8000_set_ntc_alarm` |
| Сторожевой таймер | `TIMER_CTRL[6:5]` | 0 = 5 с, 1 = 10 с, 2 = 20 с, 3 = 40 с | `enum ln8000_watchdpg_cfg_desc` |
| Режим АЦП | `ADC_CTRL[7:5]` | 0 авто-гибернация, 1 авто-shutdown, 2 shutdown, 4 гибернация, 6 обычный | `enum ln8000_adc_mode_desc` |

Показания АЦП (канал → регистр — как в `ln8000_get_adc_data`):

| Канал | Регистр | Шаг | Смещение |
|---|---|---|---|
| `IIN` | `ADC01` | 4.89 мА | — |
| `VAC` | `ADC02` | 16 мВ | +5 LSB |
| `VIN` | `ADC03` | 16 мВ | — |
| `VOUT` | `ADC04` | 5 мВ | — |
| `VBAT` | `ADC06` | 5 мВ | +1 В |
| `DIETEMP` | `ADC07` | 0.435 °C | −25 °C |
| `TSBAT` | `ADC08` | 2.933 мВ | — |
| `TSBUS` | `ADC09` | 2.933 мВ | — |

Коды 10-битные и читаются парой байт от регистра канала, поэтому каналы
пересекаются по байтам — это свойство аппаратуры, а не ошибка модели.

## Что делает драйвер

```text
open()              чтение DEVICE_ID (ожидается 0x42)
configure()         пороги, защиты, петли регулирования, АЦП, отметка инициализации
enable_switching()  SYS_CTRL → switching + проверка по SYS_STS
status()            SYS_STS / SAFETY / FAULT1 / FAULT2 / LDO
read_adc(ch)        показание канала
set_iin_limit()     смена лимита тока на ходу
soft_reset()        LION_CTRL = 0xC6 + BC_OP_2[0] = 1 (пауза ≥ 10 мс — на вызывающей стороне)
standby()/close()   перевод в standby; Drop делает то же при выгрузке
```

## Честные ограничения

* **Согласование напряжения — не наша задача.** 9/11 В с блоком согласует
  Type-C/PD-часть платформы (PM8150B). Без неё LN8000 может держать уже
  согласованное напряжение или работать в bypass 1:1 от 5 В — это зафиксировано
  в дорожной карте проекта.
* **Сторожевой таймер** по умолчанию выключен, как и в Android-драйвере. Если его
  включать, периодическое обслуживание — задача вызывающей стороны: ядро
  драйвера не спит.
* **Реальные значения регистров** подтверждены по исходнику драйвера; проверка на
  живом чипе ещё не выполнялась.
